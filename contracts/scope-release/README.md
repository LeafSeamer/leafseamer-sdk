# 注册授权与局部最终释放顺序

本包接续 [scope-storage](../scope-storage/README.md)，把“读取通过后再发生撤权”的间隙落实为可执行的单一出口顺序参考。`approved=false`、`runtime_ready=false`；本地线程、SQLite 和明文 socket 检查与产品适配验收分开记录。

## 适用边界

已知事实：旧 WAL 读快照能继续读取撤销前的注册；新的 writer 读取可以拒绝已提交撤销，但事务返回后不再持锁。（来源：[固定 SQLite 检查](https://github.com/LeafSeamer/leafseamer-sdk/blob/d26c4996854e945074cb0c4fa6a6eeb7e0b8e29e/contracts/scope-storage/check.py)。）因此，数据库读取本身不能作为后续持续发送资格。

本候选要求一个受监督 owner 独占某个出口及其连接。所有本机撤权、Profile／Selector 撤销、连接换代、凭据替换、owner 失效和恢复入口都必须先经过同一个门；不得另开可写通道或绕门直接提交会使发送资格失效的变更。当前 Python 对象和锁只实现一个进程内的该顺序，**不证明跨进程 owner 唯一性**；运行域／监督器及产品路由仍须落实这一约束。

`CurrentRead` 是可信提供者的输出，包含当前 Grant、认证上下文、连接绑定及被批准正文的摘要。调用方不能把远端自报数据包装成可信结果。提供者负责完整页／帧格式、内容选择、来源一致性、订阅生命周期和发送链校验；本包保护已经编码且完成这些校验的字节，不实现完整快照消费者或 WS 状态机。HTTP、WS、TLS 适配器必须证明其实际缓冲和发送出口遵守相同顺序，不能直接以本地明文 socket 测试替代。

## 开门、排队与一次释放

1. `open` 在新 SQLite writer 切点解析注册及当前 Grant。回到门内再次核对关闭代次、期限和引用阻断集合，防止预检期间已撤权仍建立连接。绑定固定 owner epoch、subscription、connection generation、transport 与 credential 身份；同时保留服务启动、发布域、stream 与 stream epoch。一个 owner 内 transport ID 不复用。
2. `enqueue` 复制有限的不可变 bytes，返回仅在本对象内有效的句柄。入队不授予发送资格，不推进订阅 `last_sent`、ACK 或 durable_ingest。队列按项数和总字节有界，且只允许队首释放。
3. `release` 每次调用可信正文提供者，重新核完整正文摘要、连接／运行绑定，并在新 writer 切点调用注册授权，要求当前计划与原计划相等。数据库事务结束后才进入出口临界区。
4. 出口临界区重新核门代次、队首和当前单调时间，然后调用一次 `write_once`。该调用必须非阻塞、不得等待可写、不得重入门，也不得把正文转交给另一个不受门控制的异步队列。没有数据库事务跨越出口调用。
5. `close` 与这次出口调用共享同一锁和顺序编号。关闭先行则不调用出口；出口先行则只承诺关闭切点之后不再开始新调用。已进入传输层的字节可能在关闭后才被对端观察，不能声明撤回或证明对端未收到。

`SocketSink` 仅为非阻塞明文 socket 示例，每次调用检查 socket 仍为非阻塞。产品库若内部还排队、压缩、加密、切块或重试，必须把门推进到其真正受控的释放边界，或提供足够的关闭与清队列证明；此处不预先批准任何 HTTP／WS／TLS 库。

## 出口结果

| 结果 | 队列与后续行为 | 不能推断的事实 |
| --- | --- | --- |
| `handed_off` | 本次所有字节被出口接收，消费该 ticket | 对端收到、解析、应用、ACK 或持久化成功 |
| `would_block` | 确认零字节，保留队首；下次调用从当前授权完整重核 | 原授权一直有效，或可以脱离门自动补发 |
| `partial_closed` | 包括写入 0 字节的异常关闭情形；关闭通道、丢弃剩余队列，不补发后缀 | 对端没有收到前缀，或可以复用旧连接与 cursor |
| `indeterminate` | 异常、非法计数或不能证明零字节的阻塞结果；关闭并丢弃 | 零副作用、未发送或可自动重试 |

不允许 ticket 复用或跳过队首。正文批准摘要、权限／计划、凭据、运行绑定或期限错配会拒绝并关闭该通道。时钟倒退、不可用或格式错误关闭整个 owner，不回退到墙钟。默认 16 项／262144 字节是参考检查上限，尚未批准为产品容量。

## 撤销、故障与恢复

`revoke` 先在门内阻断精确注册身份、清空全部受影响连接，再执行已有 SQLite 撤销写集。结果成功才同时返回本机关闭切点与存储回执；回滚、提交观察丢失或存储不可用均不重开本机旧通道。历史安装回执不能覆盖该阻断。

本机关闭回执只表示当前 owner 内后续调用受阻，不等于数据库撤销已提交、其他服务已关门或网络已排空。已关门但持久撤销失败时需要上层保留操作结果并按原 ID 查原；持久拒绝意图、跨进程传播确认和恢复库存仍须纳入产品完整写集。

进程停止后不恢复旧句柄或队列；新 owner 必须取得新的受监督身份，重新加载当前授权及全部未决撤销库存，再通过新的连接／附着协议开门。Python 构造函数不验证该启动库存，也不能自行证明没有旧 owner 存活。故障后的自动恢复、进程强杀和断电不在本轮已验范围内。

## 验证

[检查器](check.py)覆盖真实 SQLite 重读、FIFO／有界队列、逐次授权、过期及运行绑定变化、部分写入／观察丢失、撤销失败不重开、预检期间关闭、真实双线程的两种先后顺序，以及本机回环 socket 的精确字节。线程竞争使用测试用同步屏障，有界等待只用于安排时序；它不证明产品出口的时间预算。

```text
python -I -B contracts/scope-release/check.py
python -I -B contracts/scope-release/check.py --report
python -I -B contracts/scope-release/check.py --check-report
```

默认临时数据库写入忽略的 `logs/scope-release-tests/`；`--work` 指定尚不存在的目录。回环连接和接收均有超时，环境必须允许自身 `127.0.0.1` 临时端口。`--check-report` 仅核输入摘要，不运行行为用例。报告明确列出本机线程、socket 和 SQLite 场景；真实身份、产品传输、浏览器、设备、跨进程唯一出口、崩溃与断电仍未验收。

下一步是把可信正文／连接提供者、订阅状态及持久拒绝库存接到该局部门，并归并完整传输适配与新契约选择。阶段 0 未关闭，不修改已广告的协议组合。
