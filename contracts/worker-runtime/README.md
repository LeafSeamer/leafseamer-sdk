# Worker运行契约

产品入口`@leafseamer/sdk/worker-runtime`同时生成完整worker启动范围、监督控制十三帧、SourceRuntimeBinding、source-worker八帧及C05来源身份分支。当前选择身份为`leafseamer.worker-runtime.3`，摘要绑定Schema、生成定义、解码器、字节扫描器及本说明。它独立于HTTP product1，不修改历史安装0.2、监督0.1或panel4输入；不表示这些HTTP业务接口或Seamer采集宿主已经实现。

监督通道固定`supervisor-control/0.4.0-draft.1`。完整意图保留extension_binding，顶层device_ids替换为封闭object_scope：devices包含1至64个排序唯一设备ID；data_sources包含1至64个SourceRef和0至128个DataObjectRef。相同对象的多个修订拒绝，Ref按kind、authority、database、object_id、revision、digest的ASCII元组排序。Controller只消费devices，Seamer只消费data_sources；解码上下文须由本机可信装配提供。Ref的当前原件、批准范围、数据对象与来源的归属关系仍须权威提供者核验。不得把公开摘要或调用方自报的context视为授权。

控制帧保留完整scope、channel、sequence、message_id及reply_to；协议整数不转JavaScript Number。完整LAUNCH_REGISTER携带不可变意图与短授权，CREATE另要求原物化evidence、challenge及监督器持有的load_id。SDK提供结构与绑定检查，监督器必须再核真实peer、当前fence、时间窗口和一次创建账本。缺物化提供者不能以调用方传入的ID代替实物核验。

来源通道固定`source-worker/1`。CAPTURE、CAPTURE_ACK、CANCEL、STOP为核心发出，其余四帧由worker发出；消费者必须传入当前状态允许的具体expectedType。所有帧包含精确运行绑定、会话和正U20序号。CAPTURE含source、query、mapping、capture policy及domain Ref，窗口最长10秒，结果预算最多10000行、8MiB原字节。CAPTURE_RESULT使用规范base64、原字节长度及SHA-256；metadata只接受content_type和可空source_revision，coherence为transaction_snapshot、single_response或unproven。complete和摘要仍是候选声明，核心必须核字节摘要、固定查询及实际协议完整性后持久接纳。

CAPTURE_FAILED的reason仅接受timeout、source_unavailable、budget_exceeded、cancelled、outcome_unavailable、invalid_response或policy_rejected，last_stage仅接受queued、connecting、querying、receiving或validating。不得附带任意异常正文。ACK必须绑定核心CaptureReceiptRef。取消保留原capture ordinal，STOP_ACK区分executing与awaiting_ack并拒绝重复capture身份；停止采集不证明设备效果已排空。

SourceRuntimeBinding的scope与各具名Ref属于同一Seamer权威，生产者在真实worker准入后持久登记。C05来源绑定的target明确区分device和data_source；后者包含SourceRef、SourceRuntimeBindingRef、SourceObservationBindingRef，delivery_semantics只能sampled。公开HTTP旧接受集仍不能直接消费本入口的新绑定，业务采用必须选择本契约并完成来源writer接线。

解码器拒绝重复键、额外字段和越限正文，不裁剪。监督帧最多256KiB、完整fence最多256项，来源普通控制帧64KiB；CAPTURE_RESULT最多16MiB，包含base64及元数据。解析预算分别为控制1秒、大结果5秒，属于开发实现上限，不能代替运行环境负载验收。连接序号、原请求摘要、当前配置、撤销、持久水位和缓存丢失处理由业务消费者实施，不因Schema通过而自动重试、恢复、准入或开放设备出口。

`base.schema.json`是固定历史类型的本地引用闭包，来源提交及文件摘要见`source.json`；`scripts/worker-runtime-schema.mjs`是本版本修订的生成定义。构建产物包括静态验证器、TypeScript类型、完整Schema与独立选择。解码不依赖运行时动态编译或外部Schema下载。


当前产品选择`leafseamer.worker-runtime.3`使用监督控制0.4，共13种帧，增加LAUNCH_LOAD／LOAD_RESULT；0.2和0.3生成定义保留，HTTP product1接受集不变。CREATE须带本监督实例已持有的load_id。

LAUNCH_LOAD按begin／chunk／finish／release分支交接完整加载材料：begin固定LaunchKey、load_id、完整原字节摘要、1字节至8MiB长度及当前物化证据／challenge；chunk为至多65536字符的规范base64，offset须严格连续；finish只封结或查询同次后台校验，不重新分配ID；release关闭该次保护且不能复活；后台校验尚未退出时返回pending，只有released才确认句柄已释放。撤销先关闭资格，后台校验结束后丢弃结果并释放句柄。传输从begin起固定十秒，不因分片或轮询续期。正常控制帧仍至多256KiB，监督查询与撤销可在分片之间处理。

材料`leafseamer-worker-load/1`包含实际root_path／root_identity、原manifest和FileInventory；后两者复用安装导入唯一定义。SDK严格解析结构，监督器仍须核当前意图、fence及物化证明，计算完整材料和清单／库存摘要，匹配指定worker入口，核实际文件内容与根身份并持有句柄。ready仅表示该监督器持有内容保护，不签发人员、设备或创建授权；释放、撤销、实例退出后不可再用原load_id。
