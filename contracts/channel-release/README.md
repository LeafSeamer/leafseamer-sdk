# 订阅交付与确认接线

本包将固定的 [订阅状态模型](../event-channel/README.md)、[释放门](../scope-release/README.md) 和 [持久恢复所有者](../scope-recovery/README.md) 接到同一条发送／ACK 路径。候选仍为 `approved=false`、`runtime_ready=false`。成果是可执行设计参考与失败用例，不是已上线的订阅服务。

## 状态提交边界

[Session](bridge.py) 接管已经建立基线的订阅副本，独占其后续发送状态。输入订阅必须来自内部订阅管理器，不能从远端序列化对象恢复。原对象在 Session 建立后不再作为可写状态来源。所有访问 SQLite 的方法只能在建立 Session 的 owner 线程执行；其他线程可以通过既有 Gate 关闭出口。

入队先验证完整帧和可信正文，用影子订阅检查游标链，再保存规范 JSON 字节。入队、暂时不可写及重新授权都不修改真实 `last_sent`、已交付映射或 ACK 游标。释放时重新读取当前资格和固定正文，并在真实订阅的副本上再次执行 `sent()`。只有门内单次出口明确接受完整字节，才把该副本提交为真实发送状态。

| 出口结果 | 发送状态 | 队列与后续操作 |
| --- | --- | --- |
| 完整接受 | 登记该帧的游标和摘要 | 移除队首，仍需独立 ACK |
| 明确零字节阻塞 | 保持原状态 | 保留队首，每次重试重新读取资格和正文 |
| 部分接受，包括返回零 | 保持原状态 | 关闭本连接、清空整队列，不补发后缀 |
| 异常或无法解释的返回值 | 保持原状态 | 关闭本连接、清空整队列，不猜测成功 |

完整接受仅代表已提交给指定传输出口，不证明对端收到、应用或持久化。出口接受后发生关闭，已经发送的历史仍保留；`state().usable` 同时反映门的关闭状态，不能把历史游标当作继续发送的资格。若进程在出口接受后、内存状态提交前退出，沿用 Owner 的未正常停止恢复，不恢复旧队列或自动重发。

## 正文与来源

构造 Session 时分别注入当前授权提供者和正文读取器。后者按完整帧的 JCS 摘要读取独立可信日志，返回 `FrameBody`，其中的完整帧必须与排队帧规范字节相同；不会因 Python 把 `true` 与 `1` 判为相等而混淆正文。调用方不能用自己提交的帧直接制造批准对象。正文的发布服务、数据库、运行域、启动代次及流身份也须与当前连接一致。

接线层验证固定帧 Schema、负载摘要、绑定、前后游标和阶段，并执行以下范围检查：

- 实体更新必须精确匹配可信读取记录，属于当前 Selector 的实体集合，并满足当前／未决／历史窗口谓词。
- 实体移除必须绑定可信原记录的完整实体身份和不倒退的修订。提供者证明移除前的范围归属；帧游标来自同一日志条目，不能拿无关记录拼装墓碑。
- `source.event` 只允许完整规范来源订阅，来源记录必须位于获批集合，完整 `SourceKey` 匹配事件与当前发布实例，且序号处于已同步的连续区间。
- `sync.ready` 必须绑定当前基线与补齐截止游标的可信完整性记录。摘要、游标相连和本地检查均不能独立证明日志没有缺项。

真实领域记录、关系引用可见性、移除前成员关系、来源映射以及补齐完整性仍由可信数据库读取器负责；本包提供者使用明确合成数据，不声称已经实现该读取器。授权变化必须路由到同一 Gate 关闭路径，仅改变一个未接线的权限缓存不能提供出口顺序保证。

## ACK、同步屏障及连接替换

ACK 只查询真实已交付映射，不查询排队影子。每次重新读取当前授权和注册状态，在副本上应用 ACK，再在 Gate 锁内检查关闭状态、版本和期限后提交。数据库事务在进入该锁之前结束。检查期间发生撤权，ACK 不推进。

同步屏障可以排在补齐数据之后，但其后暂不接受新帧，直到该屏障已经完整交付并收到正确类型的 ACK。这样不会把原来按 `reconcile` 编码的排队帧在 ACK 后当作 `live` 发送。普通 ACK 后从真实订阅和剩余队列重新构建影子。保留原模型的 256 项交付映射上限，本包不另行发明保留策略。

同一 Owner 对每个订阅 ID 只登记一个 Session。新的连接代次必须严格增加，旧 Session 先关闭并清空队列，然后才允许新出口建立。新出口建立失败也不重开旧出口；旧 ticket 不能用于新连接。已关闭的代次登记保留到 Owner 结束，不能复用旧代次。

Session 锁的顺序固定为 Session → Gate。数据库由 owner 线程编排，外部撤权只使用 Gate，不反向取得 Session 锁。内部适配访问了固定版本 Gate 的私有锁和版本；这不是稳定 SDK API，来源变化时必须重新审查接线。

## 检查与未完成范围

[检查器](check.py) 使用真实临时 SQLite 文件、真实订阅模型和显式合成接收器，覆盖人员／服务／规范订阅、阻塞后资格变化、部分写入、正文与身份变异、实体移除、规范来源事件、同步屏障、连接替换，以及真实线程在重读期间和完整交付之后关闭门。默认临时文件写入忽略的 `logs/channel-release-tests/`；[报告](report.json) 绑定本包与固定来源的完整输入摘要。

```text
python -I -B contracts/channel-release/check.py
python -I -B contracts/channel-release/check.py --report
python -I -B contracts/channel-release/check.py --check-report
```

`--check-report` 只核验摘要。行为复验必须实际运行检查器。已交付映射与 ACK 在本参考中仍为内存状态，`durable_ingest` 仅校验协议中的 ACK 类型，不证明消费端落库。

产品 HTTP／WS／TLS 分帧、缓冲排空及物理关闭，真实身份认证，快照分页完整性，持久消费事务，生产 DDL／迁移／备份，浏览器和设备均未验收。出口必须满足 Gate 的单次非阻塞约束，不能转交给未受门保护的异步队列。阶段 0 仍未关闭；本包不改变既有协议原件或宣称完整 SDK 已获批准。
