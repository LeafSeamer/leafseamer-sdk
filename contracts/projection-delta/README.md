# 状态投影增量与确认事务

本参考接续 [完整快照消费](../snapshot-consumer/README.md)，把后续 `entity.upsert`、`entity.remove` 和 `server.sync.ready` 接到实际 SQLite 投影及 `projection_applied` ACK。保持固定 SDK 帧格式，候选为 `approved=false`、`runtime_ready=false`。

## 基线与连续交付

[Projection](projection.py) 只能从当前仍有效、已经原子应用的快照初始化。原快照对象、当前 slot 构建代及活动指针均须一致；仅持有数据库文件或游标不能恢复授权。已初始化的同一有效基线再次构造 Projection 时查原状态，不把已消费游标重置到快照起点。进入增量阶段后，调用方应只读取 Projection 的当前视图，原快照记录保持不可变的历史基线。

原始帧先经过严格 JSON 解码、当前 Schema、完整连接绑定、负载摘要及阶段验证。新帧的 `previous_cursor` 必须等于已提交前沿，`cursor` 必须更大；允许过滤后的数字跳跃，不要求加一。完整规范帧作为交付身份保存，同 cursor 不同正文是协议冲突。保留期内的精确重复帧返回原 ACK，不重复更新投影，也不回退前沿。

起始阶段为 `catching_up`，数据只能标记 `reconcile`。同步检查点必须引用实际已应用的基线并位于同一交付链，提交后才进入 `live`；之后新数据必须标记 `live`。旧检查点的精确重传仍可查原，但另一个新检查点不能在实时阶段再次切换。这里的 `live` 只表示投影同步状态，不解除运行暂停，也不授权设备动作。

## 修订与墓碑

所有比较沿十进制字符串转精确整数，完整 Record 原样保存。对象身份在当前基线中按 kind、id 和 epoch 核对，同 kind／id 换 epoch 拒绝。下列裁决适用于展示投影，不改变领域对象本身的修订。

| 输入情况 | 当前投影处理 |
| --- | --- |
| 更低修订的更新或移除 | 忽略实体变化，仍按连续帧提交进度 |
| 相同修订、相同更新正文 | 幂等保留 |
| 相同修订、不同更新正文 | 冲突，关闭当前消费资格 |
| 当前显示对象收到同修订移除 | 保存墓碑并隐藏；离开筛选范围不要求伪造领域修订 |
| 墓碑收到同修订更新 | 保留墓碑，防止迟到复活 |
| `left_scope` 后收到更高修订更新 | 允许重新显示，由当前已授权发布者证明重新进入范围 |
| `deleted` 后收到更新 | 即使修订更高也拒绝复活；重新创建必须使用新对象身份 |

不存在于基线的移除同样保存墓碑。墓碑也计入对象容量，不能靠大量删除绕过限制。这些保护绑定当前快照构建代；新的完整可信快照重新建立状态起点，历史墓碑仍留在原代，不把此参考描述为跨全部备份与恢复的永久身份注册。

## 三表写集与失败语义

[附加三表](projection.sql) 分别保存交付前沿、当前对象／墓碑和完整帧／原 ACK。在同一个新 writer 事务内更新对象、登记 ACK、推进前沿和阶段，提交前再次核对有效基线、slot 代际和期限。任何中间故障回滚整个写集，不能只记录游标或提前返回 ACK。不会继承或回滚调用方已有事务。

提交完成后才返回 `projection_applied`。提交观察丢失不返回成功；同一有效连接重投原帧时查到原 ACK，不重放对象变更。协议冲突、超限或资格失效关闭当前可见投影；明确注入的事务故障及 SQLite 暂时故障可以重试同一帧。新连接或新快照使旧代失效，不能用历史 ACK 继续旧链。

投影视图在同一短读事务内取得代际、游标、阶段和全部当前记录，返回前结束事务。已经交给界面的副本无法撤回，实际 UI 清理与 ACK 网络发送仍需当前资格和出口接线。数据库事务内不执行网络或设备操作。

## 证据与剩余边界

[检查器](check.py) 覆盖十二类 Record、低修订忽略、同修订冲突、范围墓碑、删除身份、连接及前驱错配、同步阶段、重复确认、三个逐写入故障点、提交观察丢失、第二 SQLite 连接观察、撤权和代际替换。端到端用例从固定快照开始，经实际服务端订阅及释放门把补齐帧、检查点和实时帧交给本消费器，再将实际 ACK 交回服务端，逐次核对两端游标与实时状态。

候选上限为帧 64 KiB、交付历史256条／1 MiB、对象与墓碑32768项／8 MiB；任一超限即停止当前消费，需受控重同步。完整生产容量、历史 GC 和迁移尚未批准。十二类结构与消费事务通过，不证明所有领域原件、动态 Schema 和真实发布权限已经验证。

```text
python -I -B contracts/projection-delta/check.py
python -I -B contracts/projection-delta/check.py --report
python -I -B contracts/projection-delta/check.py --check-report
```

[报告](report.json) 保存行为结果和完整输入摘要；`--check-report` 只核对摘要。本包限于 `status_projection`，不能因为投影使用了 SQLite 就生成 `durable_ingest`。规范来源消费者仍须把 inbox、来源连续性、固定决定与相关执行／额度写集合并后确认，不能复用本入口吞掉规范触发。浏览器存储与渲染、真实认证、HTTP／WS／TLS、设备及断电均未验收；全系统阶段 0 仍未关闭。
